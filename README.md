# MARKET MAKERS

複数の会社が同じ市場で、仕入れ・製造・投資・販売競争を行うブラウザ向け経営シミュレーションゲームです。

プレイヤーは1社の社長となり、限られた資金と手番を使って会社を経営します。全3期の経営終了後、最も多くの自己資本を残した会社が勝者です。

> 本作は、経営研修で扱われる考え方を参考に独自設計した学習ゲームです。公式MGのゲーム、教材、数値、画面またはルールを複製したものではありません。

## ゲームモード

### 1人で練習

プレイヤー1社とAI企業3社で対戦します。Firebaseを設定しなくてもプレイできます。

### オンライン対戦

同じWebサイトへ接続した2～6人が、ルームコードを使って参加します。

- ホストがルームを作成
- 参加者が6文字のルームコードを入力
- 参加者が揃ったらホストがゲームを開始
- ゲーム状態と販売コンペをリアルタイム同期

オンライン対戦にはFirebase AuthenticationとRealtime Databaseを使用します。

## 主な機能

- 1人対AI企業3社
- 2～6人のオンライン対戦
- ルームコードによる参加
- 1手につき1つの経営判断
- 特徴の異なる複数市場
- 材料購入・製造・販売
- 採用・設備投資
- 広告・研究開発・社員教育
- 全参加者による秘密入札
- 市場ごとの価格上限と需要上限
- 現金・在庫・借入の管理
- 期末の固定費・在庫費・借入利息
- PQ・VQ・F・Gによる損益表示
- 自己資本による会社順位
- GitHub Pagesへの自動デプロイ

## ゲームの進め方

### 1. 会社を設立する

社長名を入力し、1人用またはオンライン対戦を選択します。各社は同じ条件から経営を開始します。

### 2. 経営行動を選ぶ

自分の手番では、次の中から1つだけ実行できます。

| 行動 | 内容 |
| --- | --- |
| 材料購入 | 市場と数量を選んで材料を仕入れる |
| 製造 | 材料を消費して製品を作る |
| 販売コンペ | 市場、販売数、価格を指定して入札する |
| 採用 | 社員を増やして製造能力を高める |
| 設備投資 | 機械を増やして製造能力を高める |
| 広告 | 同価格の入札で有利になる |
| 研究開発 | 広告力も同じ場合に品質で有利になる |
| 社員教育 | 製造能力を高める |
| 銀行借入 | 現金を30万円増やす。期末に利息が発生する |
| 何もしない | 資金を使わずに手番を終了する |

### 3. 販売コンペを行う

販売コンペが始まると、参加者全員が販売数と販売価格を秘密入札します。

落札順位は次の優先順で決まります。

1. 販売価格が安い会社
2. 広告力が高い会社
3. 製品品質が高い会社

市場需要がなくなった時点で販売終了です。高価格で大きな利益を狙うか、低価格で確実に販売するかを判断します。

### 4. 期末決算を行う

各社が10回行動すると1期が終了します。期末には次の費用が発生します。

- 社員の人件費
- 設備の維持費
- 広告・研究開発・教育の維持費
- 製品在庫の保管費
- 借入金の利息

決算画面では次の数値を確認できます。

| 記号 | 意味 |
| --- | --- |
| P | 販売単価 |
| Q | 販売数量 |
| PQ | 売上高 |
| VQ | 変動費総額 |
| F | 固定費 |
| G | 利益 |

### 5. 最終順位を確認する

全3期終了後、現金、在庫、設備価値、借入金から自己資本を計算し、会社順位を決定します。

## ローカルで実行する

追加パッケージやビルド作業は必要ありません。

```bash
python3 -m http.server 8000 --directory dist
```

起動後、ブラウザで次のURLを開きます。

```text
http://localhost:8000
```

`dist/index.html` を直接開くこともできますが、ブラウザのモジュール読み込み制限を避けるため、ローカルサーバーの利用を推奨します。

## オンライン対戦を有効にする

### 1. Firebaseプロジェクトを作成する

1. [Firebase Console](https://console.firebase.google.com/)を開きます。
2. 新しいFirebaseプロジェクトを作成します。
3. 「アプリを追加」からWebアプリを登録します。
4. 表示されたFirebase構成情報を控えます。

### 2. 匿名認証を有効にする

Firebase Consoleで次の設定を行います。

1. **Authentication** を開きます。
2. **Sign-in method** を選択します。
3. **Anonymous（匿名）** を有効にします。

### 3. Realtime Databaseを作成する

1. **Realtime Database** を開きます。
2. **Create Database** を選択します。
3. 利用するリージョンを選択します。
4. データベースを作成します。
5. `database.rules.json` の内容を **Rules** へ貼り付けて公開します。

テストモードのまま公開しないでください。テストモードでは、第三者がデータを自由に読み書きできる可能性があります。

### 4. Firebase設定を入力する

`dist/firebase-config.js` を開き、Firebase Consoleに表示された構成情報へ置き換えます。

```javascript
export const firebaseConfig = {
  apiKey: "...",
  authDomain: "プロジェクトID.firebaseapp.com",
  databaseURL: "https://プロジェクトID-default-rtdb.firebaseio.com",
  projectId: "プロジェクトID",
  appId: "..."
};
```

FirebaseのWeb APIキーはクライアントアプリを識別する設定値であり、それだけで管理権限を与える秘密鍵ではありません。実際のアクセス制御にはAuthenticationとDatabase Rulesを使用します。

## GitHub Pagesで公開する

### 1. GitHubへアップロードする

GitHubで新しいリポジトリを作成し、プロジェクト一式をpushします。

```bash
git init
git add .
git commit -m "Initial release"
git branch -M main
git remote add origin https://github.com/ユーザー名/リポジトリ名.git
git push -u origin main
```

`ユーザー名` と `リポジトリ名` は、自分のGitHub環境に合わせて変更してください。

### 2. GitHub Pagesを有効にする

1. GitHubリポジトリの **Settings** を開きます。
2. 左側のメニューから **Pages** を選択します。
3. **Build and deployment** の **Source** を **GitHub Actions** に変更します。
4. **Actions** タブを開きます。
5. `Deploy GitHub Pages` の完了を待ちます。

公開URLは通常、次の形式です。

```text
https://ユーザー名.github.io/リポジトリ名/
```

`.github/workflows/pages.yml` が `dist` フォルダーを公開します。以後、`main` ブランチへpushするたびに自動更新されます。

## セキュリティと運用上の注意

- オンライン版は少人数で遊ぶための試作版です。
- ルームコードを知っている認証済みユーザーは、そのルームへ接続できます。
- 現在は参加者のブラウザからゲーム状態を更新する方式です。
- 公開大会や賞金付き対戦など、不正対策が必要な用途には適していません。
- 本格運用では、入札判定や資金計算をCloud Functionsなどのサーバー側へ移してください。
- 使用量や料金はFirebase Consoleで定期的に確認してください。
